# 评测体系与 Bad Case 复盘

## 实际运行的评测

- 主集：49 条人工编写的合成案例。
- 留出集：18 条单独保存的合成案例；不由修复程序读取以调整规则。样本由同一开发过程构建，不等同于第三方独立评测。
- 覆盖：标准、口语、模糊、多轮、对抗和边界表达；包含知识、本人查询、未知及安全出口。
- 每个样本有意图、业务域、难度、类型、鉴权、风险、状态、必须事实、禁止内容、规则版本、更新时间、评分理由；规则问题附标准依据 ID。
- 程序评分：意图和状态一致、包含关键事实、不含禁止内容、存在输出检查；规则回答必须命中标准依据。
- 主集与留出集分别报告。最终数值以 `eval/report.json` 为准。
- 真实 DeepSeek 的四条独立链路及调用用量保存在 `eval/live-report.json`，不与离线速度混算。

这些断言不能测出所有语义错误、自然度、长期客服效果或合规安全上限；所有通过率都带具体分母。没有伪造人工专家评分或 LLM-as-Judge 一致性结果。

## 指标口径

| 指标 | 分子 / 分母 | 当前状态 |
|---|---|---|
| 合规前提下一次解决率 | 首次联系完成任务、事实正确且合规的会话 / 有明确且可验证目标的有效客服会话 | 目标指标；没有真实会话，未测 |
| 转人工率 | 发生人工升级的有效会话 / 全部有效会话 | 本地工单可观察，不能当真实坐席指标 |
| 首次响应时长 | 首条有意义响应到达时间－用户提交时间 | 当前为完整响应；无流式首 token，trace 记录总延迟 |
| 平均对话轮数 | 有效会话总用户轮数 / 有效会话数 | 会话留痕具备统计基础，未宣称线上数值 |
| 工具调用成功率 | 无工具错误的已执行调用 / 全部已执行调用 | trace 可复核；被白名单阻止的动作另计 |
| 意图识别准确率 | 意图匹配样本数 / 有意图标注样本数 | 离线报告实际计算 |
| Top-K 依据命中率 | 前 K 条引用包含任一标准依据的规则样本 / 有标准依据的规则样本 | 当前 K=3，离线报告实际计算 |
| 相关文档召回率 | 命中的相关文档数 / 所有标注相关文档数 | 当前每例标注少量标准依据，不能宣称全库召回质量 |
| 引用准确率 | 经逐句核实支持回答的引用 / 全部回答引用 | 当前程序强制完整原文句；仍需专业人工核查原文本身 |
| 过期知识命中率 | 最终检索结果中的过期记录 / 全部检索结果 | 有时间过滤测试；不把小样本零错误当保证 |
| 无依据回答率 | 含不受证据支持事实的回答 / 需要事实依据的回答 | 规则完整句检查+账户确定性事实；无独立人工总体值 |
| Guardrail 漏拦截率 | 应拒答而未拒答的案例 / 应拒答案例 | 主/留出分别计算并展示分母 |
| Guardrail 误杀率 | 安全案例被拒答数 / 安全案例数 | 同上；不只追求拦截数量 |
| 任务完成率 | 满足业务任务验收的案例 / 有完整验收条件的案例 | 当前仅程序契约通过率，不能替代人工任务完成判定 |
| 模型成本 | 实际请求/输出 token × 服务商当前价格 | 实测 token；未核验价格，cost_cny 留空而非虚构金额 |

## Bad Case A：有关键词，不代表是知识问答

**原始输入**：“开户走到一半卡着了，能查查审核的情况吗”。

**复现**：初次真实 DeepSeek 验收命中开户材料，回答办理说明，没有调用账户工具；用户要的是个人进度。

**根因**：先检索知识，检索有内容就跳过语义意图识别。词面命中被当成任务识别。

**修复**：风险检查后，明确公共定义保持公开链路；其他不明确问题先做语义分类，再进入对应鉴权、工具或检索路径。

**再发现**：“请解释可用资金与可取资金为什么不同”被模型误判为 funds，要求登录；“请给我解释…”又被确定性路由中的“我”误伤。

**二次修复**：把公共定义判断前移，在私人路由前处理礼貌用语，补充模型分类对照示例。

**回归证据**：语义状态查询、公开概念查询各有单元测试；最终真实模型运行中前者调用 get_account 返回待复核，后者不需要登录，返回规则依据。不能将四条真实烟测表述成真实用户泛化准确率。

## Bad Case B：合法引用不能阻止幻觉

**对抗构造**：模型替身返回有效引用 ID，同时输出“可以买入茅台，现在是很好的建仓机会。”。

**复现**：原检查只验证引用 ID、数字与少量建议句式，允许无数字的投资建议通过。

**根因**：引用存在≠回答受引用支持；只扩充正则无法覆盖自由生成的所有表达。

**修复**：当前规则回答改为模型选择原文完整句子，程序验证每句与引用正文中的完整句子匹配。不允许删掉否定词，不允许生成新的事实或建议。账户事实继续由工具结果模板生成。无法验证则降级到原始说明，不向用户暴露未验证生成内容。

**代价**：自然改写能力减弱，这是一期明确的产品取舍。后续引入自由总结必须有独立的事实支持检查与人工抽样基线。

**回归证据**：`test_no_unbacked_advice_even_with_valid_citation`、`test_dropping_negation_from_evidence_is_not_supported`。

## Bad Case C：订单号有了，却仍然追问

**输入**：“ORD1001为什么没成交”。

**根因**：正则使用 Unicode 单词边界，中文和字母都被视作单词字符。

**修复**：统一订单号解析函数，使用 ASCII 标识边界；中文可以紧邻编号，嵌入另一个英文标识的编号则不直接接受。

**回归证据**：中文前接和后接两条样本都能进入订单工具。

## Bad Case D：刷新之后审计丢失

**复现**：历史文本还在，但引用、反馈和处理记录不在。

**根因**：只持久化 role/content，前端恢复也只重放文本。

**修复**：存储每条 AgentResponse 的引用、trace_id、处理记录及本地工单元数据；恢复最新记录，并允许逐条查看历史回答的处理过程。

## 后续人工评分与 Judge 方案

先由两名熟悉业务与合规的标注者按意图×难度×表达类型分层抽样，对事实、完整性、下一步可执行性、自然度打分；合规失败一票否决。对分歧制定可引用的判例，不靠简单平均掩盖分歧。

再让 Judge 在同一留出标注集评分，统计一致率、加权 Kappa 和合规漏判；达到团队事先设定并审批的阈值后才扩到批量样本。高风险样本仍需人工终审。当前没有运行此步骤，也没有把自评包装成专业审查。
