# 用户与场景研究结论 v0.1

## 研究边界

当前没有券商内部客服日志，因此本文不声称掌握真实问题占比。结论来自经纪业务流程拆解、官方资料入口、公开产品走查框架和可验证的用户任务假设。

## 角色与任务

| 角色 | 关键任务 | 失败影响 |
|---|---|---|
| 个人投资者 | 查询规则、办理业务、查询本人状态、诊断订单、获得下一步 | 等待、重复沟通、业务延误、误解规则 |
| 券商客服坐席 | 处理复杂/异常/争议问题 | 重复问答占用、峰值排队 |
| 经纪业务/数字化部门 | 降低重复服务成本、统一口径、提高自助完成 | 成本、服务质量和合规风险 |
| 合规/业务规则团队 | 审核规则、话术、风险边界和版本 | 违规、过期知识、不可追溯 |

## 用户为什么会问客服

“信息可以在页面中找到”不等于“用户能独立完成任务”。可验证的障碍假设包括：入口分散、金融术语难懂、规则不能直接映射到本人状态、跨系统状态不可见、异常原因不透明、用户不知道下一步动作。需要通过 App 走查、用户访谈和公开评论验证，不能直接写成总体事实。

## 任务分层

### A. 静态规则任务

例如开户材料、办理入口、交易时间、权限规则说明。通常不需要读取个人数据，适合 FAQ 或带来源和版本的 RAG。

### B. 个人状态任务

例如开户进度、账户状态、权限是否满足、订单状态。需要身份认证和受控工具，不能靠模型内部知识回答。

### C. 诊断任务

例如订单为什么未成交、权限为什么未通过、资金为什么不可取。需要澄清槽位、调用多个工具，并把原因码翻译成可执行下一步。

### D. 高风险任务

例如荐股、涨跌预测、收益承诺、代客操作、越权查询。必须拒答、引导到合规出口或转人工。

## 用户画像的两个维度

- 资产维度：用于适当性和业务资格判断；不作为自动营销依据。
- 生命周期维度：未开户、已开户未入金、已入金未交易、活跃交易、低频/长期持有等；用于判断当前任务上下文和下一步，不用于直接生成投资建议。

## 可验证的需求假设

1. 用户任务比“咨询”更适合定义产品边界。
2. “规则是什么”和“我能不能办”必须拆开。
3. 诊断类问题比状态查询需要更深的 Agent 能力。
4. 高风险拒答和人工交接是客服产品的核心能力，而非异常分支。
5. 个性化客服解释可做；个性化投资建议应从一期客服范围排除。
