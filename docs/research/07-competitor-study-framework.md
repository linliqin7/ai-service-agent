# 竞品与替代方案研究框架 v0.1

## 研究对象

1. 券商 App 的在线客服、帮助中心和业务办理入口；
2. 银行/基金平台的智能客服，作为流程能力参照；
3. 同花顺及问财，作为信息服务和智能交互参照；
4. 金融机构智能客服 B 端方案，作为机构采购和后台治理参照；
5. 传统 FAQ、人工坐席、电话客服，作为替代方案。

## 统一任务走查

| 编号 | 任务 | 观察重点 |
|---|---|---|
| C-01 | 开户材料 | 是否能一次说全、是否给办理入口 |
| C-02 | 开户进度 | 是否要求登录、是否能查本人状态 |
| C-03 | 我能否开通某权限 | 是否区分规则查询和个人资格判断 |
| C-04 | 我还差什么 | 是否逐项解释差距和下一步 |
| C-05 | 订单为什么未成交 | 是否澄清、查实时订单、解释原因 |
| C-06 | 订单当前状态 | 是否给状态依据和更新时间 |
| C-07 | 某股票能不能买 | 是否触发合规拒答或投顾入口 |
| C-08 | 连续追问 | 是否保留上下文、是否重复让用户描述 |
| C-09 | 无法处理的问题 | 是否转人工、上下文是否交接 |

## 记录字段

入口、是否登录、首响时间、首轮回答、澄清问题、所需数据、引用来源、规则时间、是否完成任务、下一步动作、转人工方式、上下文保留、风险提示、证据截图/链接、证据等级。

## 不能直接下的结论

宣传材料只能证明产品声称具备某能力，不能证明真实任务完成。没有实际走查或官方文档的地方，不能写“竞品不支持”“行业普遍存在”或具体比例。
