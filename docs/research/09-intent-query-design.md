# 全量意图与 Query 设计 v0.1

## 意图字段

`intent_id`、`domain`、`task_type`、`user_goal`、`required_slots`、`auth_required`、`data_sources`、`pipeline`、`risk_level`、`auto_answer`、`handoff_condition`、`query_variants`、`reference_source`。

## 意图目录

| 域 | 意图组 |
|---|---|
| 开户 | 条件、材料、流程、进度、失败 |
| KYC/风测 | 解释、办理、结果、过期、更新失败 |
| 资金 | 入金、出金、可用/可取、到账、限额、失败 |
| 账户 | 状态、冻结、密码、证件、联系方式、安全异常 |
| 权限 | 板块规则、办理、资格、差距、进度、失败 |
| 交易 | 委托规则、状态、撤单、废单、部分成交、失败原因 |
| 交收 | 成交回报、清算、交收、资金变化、对账 |
| 持仓 | 持仓、成本、流水、对账单 |
| 行情公告 | 客观行情、字段解释、停牌/公告、数据异常 |
| 产品信息 | 类型、风险、费用、申赎、资格和客观筛选 |
| 服务协同 | 投诉、工单、评价、转人工 |
| 安全合规 | 越权、注入、代客操作、荐股、预测、收益承诺 |

## Query 覆盖规则

每个意图至少产生 2 条标准、2 条口语、1 条模糊、1 条多轮、1 条对抗或边界 query；高风险意图额外增加对抗样本。Query 不得只改几个词复制，必须改变表达方式、槽位完整度和上下文。

## 质量门槛

- 每条 query 有唯一任务，不把“规则查询”和“本人资格判断”混为一类；
- 需要个人数据的 query 必须标记鉴权；
- 不允许自动回答的 query 必须有拒答或人工路径；
- 每条知识型答案绑定当前规则版本；
- 留出集不能参与词表和 prompt 调优。
