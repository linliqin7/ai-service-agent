# 券商经纪业务全量任务地图 v0.1

> 目的：建立问题空间，不代表真实流量排序。当前没有券商内部客服日志，因此所有“高频/低频”判断必须后续用证据验证。

## 一、任务分类原则

每个业务主题都按六种用户任务拆解：

1. **是什么/规则查询**：用户想理解规则、条件、费用或定义。
2. **怎么做/办理路径**：用户想知道入口、材料、步骤和时限。
3. **我能不能/资格判断**：需要把当前规则与用户本人状态比对。
4. **到哪了/状态查询**：需要查询账户、申请、订单或资金的实时状态。
5. **为什么/异常诊断**：需要根据状态、原因码、规则和上下文解释失败。
6. **下一步/人工协同**：系统无法安全完成时，给出补充信息、转人工或官方出口。

## 二、全生命周期任务地图

### 1. 开户与身份认证

- 了解开户条件、年龄和主体要求
- 开户材料、银行卡和三方存管
- 线上/线下开户路径
- 视频见证和身份认证失败
- 开户申请进度
- 开户审核不通过原因
- 多账户、销户后重新开户等特殊情况

### 2. KYC 与风险测评

- KYC 是什么、为什么需要
- KYC 信息如何填写和更新
- 风险测评如何完成
- 风险等级含义和有效期
- 测评结果查询
- 测评过期、变更或重新测评
- 信息不一致、认证失败或需补充材料

### 3. 入金与银证转账

- 银证转账是什么
- 如何入金、绑定银行卡和更换银行卡
- 可用资金与可取资金的区别
- 转账时间、到账状态和限额
- 入金失败或到账延迟
- 银行卡、账户或通道异常

### 4. 账户状态与基础信息

- 账户状态查询
- 账户冻结、休眠、限制交易
- 资金、持仓、资产和收益查询
- 登录、交易和资金密码修改/找回
- 手机号、地址、证件等资料维护
- 账户异常、异地登录和安全事件

### 5. 交易权限与适当性管理

- 主板、创业板、科创板、北交所等板块规则
- 权限开通条件和办理入口
- 融资融券等业务权限说明
- “我是否满足条件”的逐项校验
- 申请进度和审核结果
- 未满足条件时的差距解释
- 风险等级与产品/权限的适配说明

### 6. 行情与标的信息

- 当前价格、涨跌幅、成交量等客观行情
- 行情字段和图表含义
- 停牌、复牌、除权除息等公告信息
- 行情延迟、数据异常和更新时间
- 明确拒绝涨跌预测、买卖建议和收益承诺

### 7. 委托与下单

- 委托类型、交易时间和价格规则
- 如何提交、撤销或修改委托
- 委托状态查询
- 委托失败、废单、撤单和部分成交
- 资金不足、权限不足、价格限制、停牌等原因诊断
- 不执行代客下单、代客操作或替用户决策

### 8. 成交、清算与交收

- 成交状态和成交回报
- 未成交、部分成交和撤单后的资金状态
- 清算交收是什么
- T+1 等交收规则说明
- 可用/可取资金变化
- 交收异常和对账差异

### 9. 持仓、资金与出金

- 持仓明细和成本查询
- 资金流水、交易记录和对账单
- 卖出后资金何时可用、何时可取
- 出金路径、时间和限额
- 出金失败、冻结或到账延迟

### 10. 基金及其他产品信息

- 产品类型、风险等级、费用、期限和申赎规则
- 产品公开资料查询
- 用户是否满足申购条件
- 根据风险测评过滤不适配产品
- 拒绝“推荐哪只”“这个值不值得买”等投资建议
- 引导查看产品说明书或持牌投顾

### 11. 客诉、服务与人工协同

- 投诉、建议和服务评价
- 查询历史工单和处理进度
- 机器人无法识别或连续澄清失败
- 高风险、敏感、异常或争议问题转人工
- 将会话上下文、已验证身份和工具结果交接给坐席

### 12. 安全、隐私与越权

- 身份认证和敏感数据展示
- 查询本人或他人账户
- 账户信息脱敏
- 提示词注入、越权请求、规则绕过
- 代客操作、索要密码、验证码或完整银行卡信息
- 安全事件升级和人工处理

## 三、每个任务必须补齐的字段

| 字段 | 说明 |
|---|---|
| task_id | 稳定编号 |
| domain | 业务域 |
| task_type | 规则/办理/资格/状态/诊断/人工 |
| user_goal | 用户要完成的目标 |
| trigger | 触发场景 |
| required_data | 静态规则、用户数据、订单数据等 |
| auth_required | 是否需要登录或二次鉴权 |
| risk_level | L0-L3 |
| answerability | 自动回答/受控处理/必须人工 |
| pipeline | FAQ/RAG/Tool/Agent Loop/Reject/Handoff |
| failure_cost | 答错或失败的后果 |
| evidence_status | 已证实/初步证据/待验证 |
| query_coverage | 标准、口语、模糊、多轮、对抗、边界 |

## 四、一期覆盖策略

“全场景覆盖”定义为：每个任务都有安全处理路径；核心任务端到端完成；暂未接入的数据或系统使用明确的能力边界和人工兜底。系统禁止对未知任务自由编造答案。

一期优先验证四类差异最大的能力：

- 规则查询：静态知识与版本化依据；
- 个人资格判断：用户画像、鉴权和规则比对；
- 订单/账户诊断：多轮澄清、工具调用和原因解释；
- 高风险请求：合规拒答、替代出口和人工协同。

这是能力验证优先级，不是对真实请求量的结论。
