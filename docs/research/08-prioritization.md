# 需求优先级与一期范围

## 评分模型

每个候选任务按 1–5 分记录：频率证据、任务价值、当前损失、Agent 适配度、数据可获得性、风险可控性。频率没有内部日志时不打高分，标记为待验证；高风险且不可安全自动处理的任务进入“拒答/转人工”优先级，而不是被删除。

## 一期能力范围

### P0：全量安全覆盖，核心端到端

- 规则/流程查询：FAQ + 版本化 RAG；
- 本人资格和差距判断：鉴权 + 用户画像 + 当前规则比对；
- 账户/订单状态和异常诊断：澄清 + 工具 + 规则依据；
- 高风险请求：确定性风险扫描、拒答、替代出口；
- 转人工：上下文、鉴权状态、工具结果和失败原因交接；
- 未知意图：澄清或转人工，禁止自由编造。

### P1：增强体验

- 规则和知识来源展示；
- 资产/生命周期画像解释；
- 复杂问题的受控 Agent Loop；
- 规则变更影响分析；
- 评测和 Bad Case 工作台。

### P2：后续助手化

- 客观行情和公告摘要；
- 适当性约束下的产品信息筛选；
- 持仓和账户分析；
- 持牌投顾协同。

## 明确排除

真实交易执行、代客操作、直接荐股、收益承诺、未经授权的资产使用、把 mock 数据当作线上结果。

## 选择依据

一期不是“只做三个 Demo”，而是“建立全量任务地图，对所有任务提供安全路径；选择 P0 任务做端到端验证”。这能同时满足完整性和可交付性。
